# Changes from Ring Racers v2.4

Everything this port adds, removes, or changes compared with vanilla [Ring Racers v2.4](https://github.com/KartKrewDev/RingRacers/releases/tag/v2.4). Unless noted otherwise, the engine changes are in `patches/ringracers-uwp.patch`.

Where each change applies:

- **UWP builds only** (`SRB2_CONFIG_UWP`, which defines `_UWP`): Xbox-specific behavior, diagnostics, Legacy GL's Direct3D 11 port, and some of the optimizations.
- **Every platform built from the patched source:**
  - the GL2 RHI's call reductions and OpenGL ES support
  - the colormap texture caching
  - the software renderer optimizations, except inlining `R_GetTextureNum`
  - nonfatal unreachable-route errors when sending UDP packets
  - the Lua userdata set
  - the state-change and interpolation-list changes
  - Legacy GL's skybox and neutral camera-fog fixes

None of the changes alter game logic results. The optimizations of game logic do the same work in less time, so replays, netplay, and ghosts should behave as in vanilla.

Changes marked *untested* are in the latest build but haven't been tried on an Xbox yet.

## Platform and build

- **Static library for a UWP launcher.** The `SRB2_CONFIG_UWP` option and the `ninja-x64_windows_uwp_vcpkg-release` preset build the game as a static library instead of an executable. The `uwp/` launcher links it, and the executable name gets no Git revision suffix. Based on worleydl's uwp-compat branch, rebased onto v2.4.
- **Dependencies.** SDL2 and libuwp come from [worleydl/uwp-dep](https://github.com/worleydl/uwp-dep) instead of vcpkg.
- **CPU target.** The game is compiled for the Xbox One's Jaguar CPU (`-march=btver2`). Xbox Series X|S CPUs support all of its instructions. Jaguar has no FMA, so floating-point results match other x64 builds.
- **Launcher (`uwp/`).**
  - Starts SDL through `SDL_WinRTRunApp`.
  - Caches the CoreWindow on the UI thread so other threads can use it.
  - Reports the process memory budget to the game.
  - The manifest is version 2.4.0.0. It requests file system, removable storage, network, expanded resources, and microphone access (for 2.4's voice chat).
- **Build script and CI.**
  - `build.ps1` clones v2.4, applies the patch, builds SDL2 and the game, downloads ANGLE (checking its SHA-256), and generates the launcher solution.
  - Checkout, dependency-cache and artifact-upload actions use Node.js 24 releases. Visual Studio's native Developer PowerShell configures the x64 build environment and exports it to subsequent steps, replacing the MSVC setup action that still targets Node.js 20.
  - GitHub Actions runs isolated native regression tests with AddressSanitizer and UndefinedBehaviorSanitizer before building every push. The suite checks online keepalive/title behavior, Options slide timing, bounded diagnostics, and wipe math in applicable UWP/desktop and hardware/software variants; it does not run the whole game or validate Xbox hardware. [Test instructions and coverage](tests/README.md).
  - An installable [shader smoke-test PK3](tests/addons/shader-smoke/README.md) marks floors/walls with magenta/green checkers and ripple-enabled water with moving cyan/orange bands. Its four shader-only entries contain no gameplay scripts or replacement assets. Native tests load the packaged entries through the production shader parser and translate all nine target/layout pairs plus the water refraction variant; Windows CI compiles their 19 SM4 stages and publishes the PK3 as `shader-smoke-test`. Xbox visuals and loading cost remain untested.
  - Each run uploads a sideloadable `.msix` signed with a throwaway certificate, plus the linker map (`ringracers-uwp-symbols`).
  - The native regression tests build with four workers, one per core of the `ubuntu-24.04` runner, instead of two.
  - The Windows WARP renderer regressions (the translated add-on shader fixture compile, the Direct3D SM4 tests and the Direct3D 12 tests) have their own `warp` job, which waits for the Linux tests' fixtures, while the `build` job starts right away and runs alongside it instead of after both. A failed test still fails the run; the package is uploaded either way. A push takes about as long as the longer of the two Windows jobs rather than the sum of everything.
  - The Direct3D 12 WARP step's 76 negative controls run one process per runner core instead of one after another. Each control is its own harness process that replays the scenes before its own under GPU-based validation, which on WARP is CPU work, so in sequence they took about 16 of the step's 18 minutes. The runner script keeps a process per core busy, drains each one's output on the thread pool, prints it when it finishes, and reports every control that was not rejected at the end. The harness writes no files, so the processes don't collide. They also skip GPU-based validation and keep only the debug layer: a negative control runs the same GPU work as the full run up to its scene and only changes what its oracle expects, so the full run, which still validates everything, already covers it.
- **Engine build changes.**
  - Legacy GL's Direct3D 11 shaders are compiled with `fxc` at build time.
  - The DbgHelp and cpptrace libraries aren't linked.
  - Runtime DLLs aren't copied next to the library.

## Graphics

- **VibeRant D3D runs on Direct3D 12 by default** *(untested on Xbox)*. The Direct3D 12 driver now has everything the Direct3D 11 one did (the same driver table, `D3D11_*` entry points, console variables and diagnostics), so `gr_d3d12` defaults to **On** and the renderer is named **VibeRant D3D** in the renderer list and in Options → Video → Advanced, where the backend option is now **Direct3D 12** (Off keeps the Direct3D 11 driver; Once still goes back after one launch). A saved `renderer VibeRant D3D11` from an earlier build logs that it isn't a possible value and keeps the default, VibeRant D3D. A Direct3D 12 start that fails still sets `gr_d3d12` Off for the next launch, so the Direct3D 11 driver remains the fallback until it's removed after the Xbox confirmation session.
- **Legacy GL fill transparency** *(untested on Xbox)*. Solid-color fills now respect explicit translucency and HUD fade flags on every patched hardware-renderer platform. The spectator Watching underline fades away with the HUD at the finish grade instead of leaving a black bar across the rank icon. Opaque fullscreen fills keep their clear shortcut; translucent fullscreen fills blend over the whole video surface. Native sanitizer checks compare Software and Legacy GL visibility, alpha, snapping and fullscreen coverage, including the fully faded underline.
- **Hardware video options spacing**. Remove the blank menu rows before **Texture Quality** and **Sprite Billboarding**, keeping the VibeRant D3D11 options more compact. The corresponding menu indices stay aligned. Applies to every patched hardware-renderer platform.
- **OpenGL ES through ANGLE.** The game renders with OpenGL ES 2 on ANGLE, which runs on Direct3D 11, instead of desktop OpenGL through Mesa's Direct3D 12 driver as in worleydl's port. The current path does not require Shader Model 6. Xbox One UWP's D3D11 feature level is 10.1, while D3D12 in Game mode exposes higher shader models; the deferred renderer roadmap below describes that distinction. To support the ANGLE path, the GL2 RHI backend:
  - creates OpenGL ES 2 contexts
  - compiles shaders as GLSL ES 1.00
  - loads the framebuffer functions that are core in ES 2
  - uses `glClearDepthf`
  - creates textures with unsized formats
  - reads screenshots back as RGBA
  - skips `glReadBuffer`
- **SDL for ANGLE** (`patches/sdl-angle.patch`). worleydl's SDL2 for UWP is built with EGL and OpenGL ES 2 instead of WGL and desktop OpenGL.
- **Display size.**
  - The display size and refresh rate come from libuwp instead of SDL.
  - The game renders at the size of ANGLE's window surface, which can be smaller than the HDMI display mode.
  - The window is always fullscreen, which fixes a tiny loading screen.
- **VibeRant D3D11.**
  - It's the default renderer *(untested)*, since it runs faster than Software on the Xbox. Configs keep their saved renderer, so this applies to new configs. The game still starts in Software and switches after loading the config, as it does when VibeRant D3D11 is saved.
  - Legacy GL needs desktop OpenGL, which ANGLE doesn't provide. So its hardware renderer draws through a new Direct3D 11 driver (`src/hardware/r_d3d11/`) instead of `r_opengl.c`.
  - The driver follows `r_opengl.c` call for call, and its GLSL shaders are ported to HLSL.
  - It renders with its own Direct3D 11 device. Each frame is copied to a texture shared with ANGLE, which draws it to the window a frame later. If ANGLE can't open the shared texture, the frame is read back instead.
  - Custom vertex and fragment shaders from add-ons' `SHADERS` lumps are supported. At load time, pinned glslang and SPIRV-Cross translate Legacy GL's GLSL to Shader Model 4 HLSL, which D3DCompile compiles for the polygon, sky and model layouts. A missing stage uses Legacy GL's shared built-in GLSL source. A custom water program replaces the water surface's color and keeps the built-in ripple refraction: a second polygon pixel variant alpha-tests the custom result, then composites it over the captured, distorted scene with the built-in blend equations, replacing framebuffer blending as the built-in water does. A custom water vertex stage may move the surface, so its captures cover the whole current viewport rather than the CPU-projected bounds. If the scene capture or the variant's translation/compilation fails, or Reduce VFX is on, custom water draws its own output with normal framebuffer blending; invalid replacements and Ignore custom shaders keep the confirmed built-in refraction. The user confirmed on Xbox that the smoke-test PK3's custom water shader worked but removed the refraction of submerged geometry; the combined effect is untested on Xbox. Underwater/heat postprocessing always keeps its built-in shader. Engine uniforms, legacy matrices/texture coordinates, custom varyings, brightmaps, alpha tests, portal clipping and OpenGL fragment coordinates are adapted to D3D11. The Shaders setting's "Ignore custom shaders" mode keeps the built-in shaders. Invalid or incompatible shaders log errors and fall back to the built-in shader without disabling palette rendering. Arbitrary uniforms use their GLSL initializer or zero; the engine has no setter for them. Uninitialized custom uniform arrays remain unsupported because the GLSL adapter lacks array zero-initialization handling. Extra vertex attributes remain unsupported because the renderer supplies only its polygon, sky and model data layouts. Both are implementation limits that could be addressed in D3D11; neither requires D3D12. Features beyond the current Shader Model 4 compiler target are a separate limit. Compiler licenses and copyright notices ship in the package's `Licenses` directory. Native tests translate 36 shader/layout pairs plus refraction variants and check invalid input/recovery; each variant must reuse its normal vertex stage and read the water capture resources. Driver dispatch regressions cover fallback, settings, sprite/model selection, custom water capture success/failure, non-ripple/opaque surfaces, every refracting blend mode, Reduce VFX, Ignore custom shaders, whole-view captures for custom vertex stages, variant failures and postprocessing. Windows CI compiles 97 translated stages with `fxc` (78 general fixtures and 19 from the installable smoke-test PK3) and checks 36,864 actual SM4/WARP pixels across polygon, sky and model layouts, constant-buffer mapping, GL fragment coordinates, alpha tests and portal clipping. It also draws translated custom water through the production refraction variant in four split-view quadrants, comparing every composite with the built-in Software ripple oracle for all six blend modes, and checks alpha-test holes and view clamps; the previous unrefracted, framebuffer-blended custom water must fail the same oracle. Then CI builds the app. Xbox add-on visuals and loading cost are untested.
  - **Native D3D12 renderer — in progress.** The Direct3D 12 backend is being built behind **Direct3D 12 (test)** (see the VibeRant D3D12 backend entries under Diagnostics). It isn't the default. Its add-on shaders target Shader Model 5.1, so that path is past the Shader Model 4 compiler ceiling; SM6 or later would still need matching GLSL translation, compilation, resource binding and engine hooks. [Xbox UWP platform guidance](https://walbourn.github.io/directx-and-uwp-on-xbox-series-x-s/) documents D3D12 feature level 11.0 and Shader Models 5.1–6.4 on Xbox One in Game mode and Xbox Series X|S in either mode; Xbox One App mode has no hardware D3D12 path. Follow [Microsoft's D3D12 porting guidance](https://learn.microsoft.com/en-us/windows/win32/direct3d12/porting-from-direct3d-11-to-direct3d-12): check device support before using SM6 and retain a D3D11 fallback. Custom uniform arrays, additional vertex data and shader stages still need explicit adapter/engine work. Benchmark the backend against optimized D3D11 before making it the default; shader-model support alone does not establish Mesa compatibility or a performance improvement.
  - In the menus, the renderer is named **VibeRant D3D11**, as is its options header. The description above the Renderer option calls it an enhanced port of Legacy GL with 3D models, true perspective, and more parity with Software, with some features still missing or degraded, and the red text asks for visual bugs to be reported to GitHub.com/ZebulanStanphill/ringracers-uwp instead of not at all. Switching to it doesn't ask for confirmation, and the loading screen while a level's geometry is prepared has no warning, since it now has close to Software's features; upstream's Legacy GL warned that it was incomplete and broken in both places.
- **VibeRant D3D11: clipped wall light slices** *(confirmed on Xbox One X in build 94)*. Intersect each wall lighting band with the original wall, splitting horizontally where sloped boundaries cross. The second build 93 pixel capture identifies Water Palace line 1 using `WTPTU1`: splitting its narrow sloped bottom tier at the water light height (-52) produced an inverted quad, with a left bottom of -52 above a left top of -614, followed by a second band extending above the original wall. Those triangles could cover the scenery with flat brown texture pixels regardless of Batching or Shaders. The new UWP path keeps every emitted slice inside the original wall, preserves texture coordinates, lighting, alpha and solid-floor cutouts, and handles zero-height endpoints without division by zero. It uses bounded stack storage and no GPU resources or framebuffer copies; crossing slices can require additional small polygons. Native ASan/UBSan regressions check 144 fixtures, including the captured tier, ordinary walls, sloped/crossing light boundaries, zero-height ends, solid holes and queued fog/transparency. The captured case fails with the pre-fix splitter. The user confirmed that the brown walls are gone and water rendering works in build 94. A controlled performance comparison and all split-screen views remain untested for this fix. [Coverage](tests/README.md).
- **Legacy GL: polyobject ripples** *(untested on Xbox)*. Moving polyobject floors and ceilings use the existing water-ripple shader when their control sector has the matching ripple flag, including translucent planes. Both regular and polyobject planes honor Reduce VFX when selecting ripple effects. Applies to every patched platform. Native UWP/desktop regression tests check 1,600 shader, flag, alpha, geometry, and ordinary-sector/FOF cases per variant with ASan/UBSan; each changed renderer function fails these tests when replaced by its pre-feature implementation. [Coverage and test instructions](tests/README.md).
- **Legacy GL: skybox views** *(untested)*. Precipitation and things with `RF_HIDEINSKYBOX` are left out of the skybox view, as in the Software renderer.
- **Legacy GL: Better transparency ordering** *(untested on Xbox)*. Options → Video → Advanced adds the saved `gr_bettertransparency` toggle, default Off. With it on, translucent and other blended sprites and models, linkdraw attachments, and always-on-top sprites join the transparent wall/floor/polyobject pass. Keep the BSP surface order and insert objects using projected overlap, depth ranges, and plane-side checks; sort objects in each position far to near, independently of their alpha amount, with camera-depth keys for pitched billboards and deterministic display-offset ties. Use current sloped-plane and moved-polyobject geometry. Opaque objects retain the depth-buffer pass, ground shadows draw before the blended pass, and the old linkdraw depth-mask workaround is disabled. With it off, retain the previous separate object/surface passes. Works with Shaders on or off on every patched hardware-renderer platform, with per-view state consumed before the next split-screen or portal view. It adds CPU projection work, temporary per-view sorting storage, up to one comparison per affected object and transparent surface, and visible-parent lookups for linkdraw attachments; it does not add framebuffer copies. Object footprints remain proxies for model bounds, objects crossing a face are not split, and cyclic intersections and triangles inside translucent models are not fully sorted. Native UWP/desktop ASan/UBSan tests check 180 ordering, compositing, dispatch, geometry, and state cases per variant, including 128 seeded scenes; the front-object regression fails against the pre-feature dispatchers. Integration regressions verify that consecutive coplanar water pieces still share the bounded snapshot, while an inserted sprite or model ends that run and the following water starts a fresh capture. Xbox correctness and performance, including every split-screen check, remain untested. [Test coverage](tests/README.md).
- **VibeRant D3D11: fog volumes** *(untested on Xbox)*. With Shaders on, fog walls and planes remap the scene behind their actual boundaries, including colored, outward, inward and overlapping volumes. This replaces the neutral whole-view camera approximation on D3D11; desktop OpenGL and Shaders Off retain that approximation. Palette rendering uses the control sector's real colormap and Software's integer plane-distance/wall-scale rows, including split-screen scaling and per-view darkness adjustment. Fog retains the unadjusted control-sector light through sloped wall splitting and plane submission. Smooth rendering applies its tint/fade equations to the captured scene. Fog doesn't write depth, and retains portal stencil/exit clipping and the active viewport. Each face copies its conservative projected rectangle into a retained render-target-sized texture, expanding to the viewport for near-plane crossings; fully offscreen or behind-camera faces make no copies. Resolution changes recreate the texture; allocation failures fall back to the old fog shader. A valid custom fog shader owns its output and skips this compositor; Ignore custom shaders or an invalid shader uses the built-in path. Fog and water retain independent capture resources and restore ordinary blending after their composites. This adds a GPU copy per visible fog face and one RGBA texture (four bytes per render-target pixel), so busy fog scenes need performance testing. Better transparency ordering remains optional, and intersecting transparent geometry and true-perspective rasterization still differ from Software. Native sanitizer tests compare 24,960 fog-row samples and 16,384 pixel-remap samples with production Software tables and check captures, failures, blend restoration, custom-shader dispatch and the newer wall splitter. Windows WARP tests execute the actual SM4 shader with palette/smooth rendering and viewport isolation, and reject reciprocal-depth remapping. Xbox correctness, performance and every split-screen visual check remain untested.
- **Legacy GL: title screen background flash** *(fix untested on Xbox)*. Opening the title screen briefly showed the title map's background lit during the fade-in on VibeRant D3D11 and D3D12, but not Software. Some 3D-floor sides were first lit from a neighboring sector's not-yet-prepared lighting, so they missed the black fog until the next frame; the fade-in holds that first frame. The fix prepares that lighting before use, and a native test replays the title map. [Coverage](tests/README.md).
- **Legacy GL: fog with Shaders Off and desktop OpenGL**. The title-screen background starts black and fades in once. A cached control sector for one inward-facing neutral fog block caps surface light, applies its colormap, attenuates the sky once and omits that block's boundary polygons. This whole-view approximation has no framebuffer copies or per-polygon FOF searches; colored/outward/overlapping fog retains the older paths. With Shaders Off, fog can differ from Software in color, brightness and boundary placement. This is an accepted quality tradeoff.
- **Legacy GL: palette rendering**, ported from SRB2's hardware renderer.
  - Toggled by `gr_paletterendering` (Options → Video → Advanced → Palette Rendering). It's on by default and needs Shaders on.
  - As in the Software renderer, colors are limited to the palette, and surfaces are lit through the colormaps.
  - Palette flashes and the color profile apply to the whole frame. Without palette rendering, Legacy GL shows flashes as a white or pink overlay and has no other flash palettes.
  - On VibeRant D3D11, brightmapped pixels use the base colormap's full-bright colors as in Software, instead of the surface colormap's brightest level, so a sector's tint or fade no longer discolors them (e.g. Skyscraper Leaps' `SKLWAL03` and `SKLWAL04` walls). Each light table carries that row as a 33rd row. A Windows WARP test runs the production shader and rejects the old row. *(untested on Xbox)*
  - *(fix untested on Xbox)* Encore's color remap is baked into the cached textures, and palette rendering kept them unless the palette changed. So playing a track again with Encore toggled reused the other mode's colors, e.g. Metropolis in Encore with its normal colors after a normal race, or the reverse. The cache is now remade whenever the Encore remap changes, as Software and Legacy GL without palette rendering effectively do at every level start.
- **Legacy GL: sprite brightmaps** *(untested on Xbox)*. Apply SPRTINFO brightmaps to sprites, including Skyscraper Leaps' Ark Arrows. With Shaders on, brightmapped pixels ignore the sector's colormap tint, fade and light as in Software, in both palette and smooth rendering. Roll-rotated brightmaps share the base sprite's exact raster transform, pivot, flip, bounds and origin, even when the map has different header offsets or opaque pixels. Companions are cached per rotated base and brightmap; source reloads and rotated-patch purges reclaim them safely. Missing maps and maps whose dimensions differ from the original sprite fall back to ordinary lighting while the sprite stays visible. Software rendering is unchanged. Native sanitizer regressions cover all nonzero roll angles, pivot selection, shared maps, pixel alignment, cache reuse/reload and binding with Batching on and off.
- **Encore brightmap regressions.** No renderer behavior change: Encore's remap is already applied to the sprite texture before brightmap lighting, so glowing pixels retain the remapped colors. Native tests run the production sprite selection, mapped texture cache, column conversion and full-bright light-table conversion against Software's full-bright selection, checking every palette index, both palette settings, ordinary/Encore/exempt sprites, cache reuse and in-place remap changes. Controls that omit or repeat the production texel remap must fail. The Windows SM4/WARP suite also checks 10,752 rendered pixels across those modes with colored tint and fade; controls that lose or repeat the remap only in glowing pixels must fail in both palette modes while leaving the other pixels correct. Xbox visuals remain untested.
- **Legacy GL: springs hidden inside walls** *(untested on Xbox; the first build missed Metropolis's bumpers, see the next entry)*. Metropolis's big yellow bumper blocks have silver springs inside them, which Software hides, so the blocks seem to bounce you. Legacy GL drew the parts of a spring that stick out through the block's faces when the block was seen at an angle, since it depth-tests the camera-facing sprite per pixel while Software decides from the spring's origin. Springs (things with `MF_SPRING`) are now hidden as Software hides them: a solid wall or opaque 3D floor side that Software draws in front of a spring also covers the part of the spring behind its outline. Other sprites are unchanged and keep per-pixel depth testing, as do springs behind translucent or see-through sides. The sides are recorded as the level is walked and each spring subtracts their outlines from its quad, so lighting, fog, colormaps and brightmaps are as before. A native test covers a spring inside a box seen at an angle, a spring in front of a wall, a spring partly behind a wall's edge, and an ordinary sprite, each with a control that must fail.
- **Legacy GL: springs behind two-sided walls** *(untested on Xbox)*. The entry above only recorded one-sided walls and 3D floor sides, but Metropolis's yellow bumper walls are the upper walls of two-sided lines (the sectors behind them have ceilings at 144–176 units, and the grey diagonal springs are stacked just behind those lines, 192–450 units up), so the first build still showed the springs' tips. Software clips sprites by a two-sided seg's upper and lower walls too (its `SIL_TOP` and `SIL_BOTTOM` silhouettes), so springs now subtract those walls' silhouettes as well. The native test records a two-sided upper and lower wall through the production seg code and checks the spring is hidden behind each.
- **Legacy GL: nearer 3D floor sides and planes paint over springs** *(untested on Xbox)*. The grey diagonal springs inside Metropolis's yellow bumpers were still showing. Each bumper is a wedge-shaped 3D floor, and Software doesn't test them one by one: `R_CreateDrawNodes` puts a sprite in its draw list before the *farthest* 3D floor side it sorts behind, and everything after that, every nearer 3D floor side and plane, is then drawn over the sprite. Seen along the wall, the nearer wedges' faces tile over the spring. Springs now follow that: the farthest 3D floor side or plane that Software would sort the spring behind decides, and every nearer one recorded before it is subtracted from the spring too. Opaque 3D floor planes are recorded for this as polygons (the top and bottom of each 3D floor, sloped ones included, long polygons split in pieces), and a plane sorts a spring behind it by Software's test: it shares screen columns and rows with the spring, is partly nearer than the spring's origin, and the spring lies wholly under it with the camera above, or over it with the camera below. Sides of ordinary walls are still tested one by one. The native test replays Metropolis's nine wedges (nearest first, each one's planes before its sides) with the spring at the map's quarter object scale from eight cameras in the pit (oblique and grazing along the wall, above and below the first row, and head-on) and checks that nothing of the spring is left showing, where testing each side on its own left about half of a full-size spring visible along the wall; it also covers a plane over and under the camera, sloped planes, a plane that the spring pokes through, long polygons, and the draw order of two sides, with and without a plane.
- **Legacy GL: spring clipping no longer overruns a stack buffer** *(untested on Xbox)*. On an Xbox One X the game closed without writing a crash log, twice, while the player bounced off springs on Metropolis. The crash logger cannot see a stack cookie failure, which ends the process at once. An AddressSanitizer run of the production spring clipping on random views reproduced it: cutting a spring's triangle by the silhouettes of 3D floor planes wrote past the end of a 36-corner buffer on the stack. Each cut was assumed to add at most one corner, which is true of an exactly convex polygon, but a plane polygon with a long edge split into many collinear corners (as GL subsector polygons often are) gives the silhouette many nearly identical planes, rounding leaves the cut corners slightly out of line, and a later plane then crosses the outline several times; single cuts added three or four corners. The clip now takes the capacity of its output and gives up instead of writing past it, as does the clip of a silhouette to the near plane (a silhouette that does not fit is ignored), and a triangle whose cuts would overflow is kept whole for that silhouette, as when it misses it. In that rare frame a sliver of spring may show where Software hides it. The native test calls the clip with too little room next to guard slots, replays the smallest fuzzed scene that overflowed, and sweeps 3000 random views (the replay and the sweep each overflow under AddressSanitizer without the fix), and a fifth control that tells the clip it has more room than its buffer holds must fail.
- **Legacy GL: palette fade maps.** On UWP, with Palette Rendering on, the level fade-in at the start of each race and other palette fades such as demo exits use Software's fade-map rows instead of a black/white translucent overlay. Cache each lump as a 256-column texture, remap the current screen before the HUD, and return master-palette colors so the final screen-palette pass applies flashes and color correction once. Clamp strength to the available rows. Keep the overlay with Palette Rendering off or if the lump or driver resources are unavailable; the fade trace records `path=exact` or `path=overlay`.
- **Legacy GL: portals.** On UWP, linedef special 40 portals (Marble Garden Zone and Media Studio each have one pair) show the area they connect to, instead of the entrance line's wall. The approach, drawing each portal's view through the stencil buffer, is inspired by [SRB2Kart Saturn](https://github.com/Indev450/SRB2Kart-Saturn)'s portals.
  - Each frame first finds the visible portal lines without drawing, then draws each portal's view before the view it's seen from. The portal's opening, the entrance line's front-sector floor-to-ceiling span, is marked in the stencil buffer, depth is reset to far inside it, and the destination view is drawn only there. Then the opening's own depth is written over it, so the surrounding scene is hidden behind the portal and drawn in front of it as usual.
  - The destination view uses Software's pairing (the first other special-40 line with the same first tag) and transform (rotated about the lines' centers, raised by the difference in their front floors).
  - Geometry behind the exit line is cut off on the GPU by a clip plane (`SV_ClipDistance`). Lines, BSP nodes and things entirely behind it are skipped on the CPU, along with the exit line itself.
  - Confirmed on Xbox One X. The player model can disappear at some positions and angles near a portal, as it also does in Software.
  - `maxportals` (default 2) limits how deep portals inside portals go, and 0 turns them off. Portal views use the regular sky, as in Software, which only shows skyboxes in the main view. Maps without portals skip the search.
- **Legacy GL: sky patch offsets** *(alignment confirmed on Xbox)*. Both sky-dome hemispheres and the flat-sky fallback honor Software's single-patch header offsets. Water Palace's `WPZSKY1` patch has a 16-pixel vertical offset: hardware now places the horizon at texture row 128, as Software does, instead of row 112. Native tests use Software's production sky setup across 52,650 vertices and signed offsets, including odd texture heights. Sky setup multiplies signed patch offsets by `FRACUNIT` instead of left-shifting negative values, avoiding undefined behavior. The user confirmed the revised background position on Water Palace; the latest Xbox test also confirmed that the background is no longer cut off by water.
- **Legacy GL: empty sky horizon boundaries** *(Water Palace cutoff fixed on Xbox)*. Software ignores empty two-sided boundaries whose floor geometry and surface properties match, even when their sky ceiling heights differ. Hardware previously extended opaque floors from those lines to the horizon, covering the lower sky/background before water could refract it. Use Software's fake-flat and empty-line checks before extending at sky boundaries. Of Water Palace's 23 horizon lines, the 22 empty boundaries no longer create those opaque extensions; its real boundary still extends. One-sided and ordinary non-sky horizons keep their existing behavior. Applies to every patched platform. Native sanitizer regressions use the actual 2.4 map boundary properties and Software's production line-acceptance logic, with lighting, colormap, tag, slope, texture, camera-side and fake-flat cases. Replacing the production draw condition with its previous implementation fails the tests. This addresses the reported above-water cutoff separately from sky alignment and capture feedback; an earlier Xbox test confirmed that the background was no longer cut off by water. ## Files and startup

- **Data folder.** Game data, config, and saves are read from and written to `E:\ringracers`. The `-home` parameter and the `RINGRACERSWADDIR` variable are ignored. The save folder is created before the game checks that the config is writable.
- **Log location.** The log is written to `E:\ringracers\latest-log.txt`, since the working directory is the read-only package folder.
- **Background file check** *(untested)*. There's no prompt. The main files load using their expected MD5s, and zip entries' local headers aren't read until each entry is first loaded. Those with an expected MD5 are then checked in the background at below-normal priority, reading 1 MB at a time, while startup continues. While it runs, the loading screen says B skips it (the gamepad is read directly, so B works between screen updates). If it hasn't finished when startup reaches the network setup, the game waits on the loading screen. A mismatch shows the usual error at the next loading step or after that wait. The log records each file's time and read speed, the outcome, and the wait.
- **Faster file check** *(untested)*. The music and sound files hash their names instead of their contents. They have no expected MD5, so the check couldn't detect anything in them; their hash only detects the same file being loaded twice, and they're never sent to netgames or recorded in replays. Reading all ~450 MB of them took ~25 s of the check's ~32 s on the Xbox.
- **Direct3D 12 check** *(pop-up shown on Xbox)*. Early at launch, the game looks for a hardware Direct3D 12 adapter that can create a feature level 11_0 device and command queue, logging each adapter it finds and its video memory budget. If there is none, it shows a pop-up explaining how to set the app type to "Game" in Dev Home, then flushes the log and exits without running shutdown code. Software adapters (the software flag, or Microsoft's Basic Render Driver) don't count; the Xbox GPU also reports Microsoft's vendor ID, so that alone isn't used. The launcher links `d3d12.lib` and `dxgi.lib`, since `LoadPackagedLibrary` can't load system DLLs (the first build's check failed in Game mode with error 126). The check was meant to catch Dev Home's App type, where Xbox One has no hardware Direct3D 12, but the package declares the `expandedResources` capability (since worleydl's port), which gives it a game's resources whatever the App type says. On an Xbox One X, App and Game gave the same Direct3D 12 device, the same 5120 MB memory and 3916 MB video memory budgets, and the same race speed (27.1 and 27.7 FPS on the same track), so the pop-up only shows if Xbox stops honoring that capability. Most launches mark no processors as the game's in either App type; one Game launch marked six. The check logs that (`UWP: app type signals:`) too.
- **Earlier loading text** *(untested)*. Graphics, fonts and the console start before the map data is read, so the loading screen shows text about 5 s after launch instead of 11–27 s. Reading the map data (each map's thumbnail and minimap) took 7–22 s before anything was on screen; it now runs during a **Loading maps...** step, redrawing the loading screen up to 10 times a second so the file check's skip text stays visible. The work is the same, only reordered.
- **No blue flash after the loading screen** (UWP only; improvement over vanilla) *(confirmed on Xbox)*. Vanilla's intro fills the screen with dark blue (palette color 157) for its first six tics before showing the "Produced by Kart Krew Dev and our SRB2 associates" card. On a fast boot that blue is barely seen, but on a slow boot it comes right after the loading screen, which already shows that card, so it reads as a flash between two copies of the same screen. UWP builds skip the blue and show the card from the first tic; the intro's timing is unchanged.
- **No black frames after the loading screen** (UWP only; improvement over vanilla) *(confirmed on Xbox)*. While VibeRant starts, the game finishes a few frames with nothing drawn but a clear, which showed as about two black frames between the loading screen and the intro. VibeRant D3D11 and D3D12 now skip presenting until something has been drawn, so the window keeps showing the loading screen until the intro's first card. A Direct3D 12 WARP test checks that a clear-only frame before the first draw isn't presented and that the first drawn frame is.

## Performance

These came from profiling on an Xbox One X.

### Rendering (GPU calls)

- **Legacy GL: drawing settings uploads** *(UWP only)*. On drivers that support constant-buffer offsets and writes without overwriting pending draws, drawing settings use a 2 MB buffer with 512-byte slots. The buffer is discarded only when full; repeated settings skip uploading. Other UWP drivers use a default buffer updated with `UpdateSubresource`.
- **Legacy GL: level resource precaching** *(UWP only)*. During level loading, warm wall textures and flats (including brightmaps and FOF control sectors), existing object models, and current player models and colored textures. A second pass after bot setup, player spawning and level-start hooks warms final player skins/colors before gameplay. This moves USB reads and resource creation into loading to reduce hitches during racing. It runs only with Legacy GL, and skips dedicated servers, state reloads, net snapshots and demo rewind. Models need Models enabled and a valid model entry. Sprite-textured models remain lazy because their UVs need the view-selected sprite patch; future animation frames, view-dependent FOF remaps and later-spawned objects remain lazy. Wall/flat warming uses the renderer's existing cache functions and the first sidedef/sector's remap as the common case where a cache has only one variant.

Both changes are confirmed working in the latest Xbox One X test: roughly 27–54 FPS at 1920×1200 in races, compared with about 22 FPS at 640×400 before. Level loads were not noticeably longer, and some momentary pauses remain.

The CPU cost of GL calls through ANGLE is high on Xbox, so the GL2 RHI backend makes fewer of them:

- **Skipped redundant calls.**
  - State changes, texture binds, and buffer binds that wouldn't change anything are skipped.
  - Only the vertex attribute arrays that were enabled get disabled.
  - Sampler uniforms are only set when their slot changes.
- **Things kept between frames.**
  - Uniform locations are cached per program.
  - Framebuffers are kept between frames instead of being recreated every frame.
  - Colormap and lighttable textures are kept between frames and reuploaded only when their contents change. They're freed after 300 frames unused.
- **Fewer uploads.**
  - The palette is only uploaded when it changes, and the default colormap only once.
  - Single-channel textures use `GL_RED` (`EXT_texture_rg`) instead of `GL_LUMINANCE`, which ANGLE converted to RGBA on every upload.

### Software renderer

- **Visplanes.** A new visplane clears only the columns that can be on screen, instead of all `MAXVIDWIDTH` of them.
- **Screen tilting.** Tilted views are rotated by stepping along source rows, instead of rebuilding and reading a full-screen, 4-byte-per-pixel map every time the angle changes. The output is unchanged: the same float stepping, clipping, zoom, and mirrored sampling. Large views share the work across the parallel software rendering workers.
- **Sprite sorting.** Draw nodes that share no column with the sprite being sorted are skipped without reading what they point to.
- **3D floors.** Each 3D floor plane's bounds are calculated once during node sorting.
- **Wall columns.** Unused thick-side slots are left alone, and a wall column's data is only copied when it needs remapping.
- **Masked columns.** Each masked column's clipping limits are calculated once, and read-only column data is passed straight to the drawers.
- **Texture lookups.** `R_GetTextureNum` (texture translation lookup) is inline.

### Game logic

- **`FixedMul`** is inline. Calling it cost more than the multiply.
- **Subsector lookups.** `R_PointInSubsector` remembers the subsectors of 512 recent points. Walking the BSP from its root on every lookup was about 10% of game logic. The cache is cleared whenever a level's BSP is loaded or freed.
- **Lua userdata.** A set of the pointers that have Lua userdata lets freeing a block skip asking Lua, which was about 4% of game logic.
- **State changes.** `P_SetMobjState` and `P_SetPlayerMobjState` no longer clear a 40 KB table on every state change.
  - Upstream returns without counting its call as finished when a state removes its mobj. After that, every call counted as nested and cleared the table, about 5% of game logic.
  - Each nesting depth now has its own table, and each call erases only the states it recorded.
- **Interpolated mobjs.** Mobjs record their slot in the interpolation list, so removing one doesn't search the whole list.
- **Mobj references.** `P_SetTarget` (in release builds) and `P_MobjWasRemoved` are inline. The order of reference updates around collision callbacks is unchanged, as are the `PARANOIA` checks.

### Frame pacing and threads

- **Skipped frames.** A frame skipped to catch up on game logic no longer sleeps out its frame time, which had left the game idle about 16% of the time in Time Attack.
- **No-sleep exception off.** The game sleeps to the frame cap even with V-Sync on and the FPS cap set to match the refresh rate, since not sleeping disrupted frame timing on Xbox (from worleydl's port).
- **Thread pool size.** The thread pool is sized from the processors Xbox allocates to the game, falling back to upstream's hardware count when Xbox doesn't mark any.

- **Direct3D 12: diagnostics parity** *(untested)*. The Direct3D 12 driver gains the Direct3D 11 driver's diagnostics, so the same tools work on either renderer:

- **Direct3D 12: GPU-side present synchronization** *(untested)*. With **Direct3D 12 (test)** on interop paths A, B and C, the Direct3D 12 queue and ANGLE's Direct3D 11 device now wait for each other on the GPU instead of the CPU waiting for both. One 5-second block of an Xbox One X log showed `ANGLE read waits 46, 668.20 ms total`, about 14 ms of main-thread stall per wait, while copy-fence waits were near 0 ms.
  - Two Direct3D 12 fences are shared with ANGLE's device, as the sharing probe tested: after the submission that copies a frame into a presentation texture, the queue signals the copy fence, and ANGLE waits for it before drawing that texture to the window. After the draw, ANGLE signals the read fence, and the queue waits for it before the submission that next copies into that texture. Neither wait is enqueued unless the matching signal already is, and none is enqueued on a removed device.
  - The log says `present sync: shared fences`. If the fences can't be made, it logs `present sync: shared fences unavailable (<step> 0x…)` and keeps the CPU waits. If a signal or wait call fails later, it logs `present sync: <call> failed` and uses the CPU waits for the rest of the run. Path D (readback) still waits on the CPU.
  - New `gr_d3d12_present` value `CpuSync` keeps the CPU waits even where the fences work, to compare the two (`present sync: shared fences not used (gr_d3d12_present CpuSync)`). It is read when the presentation textures are made, at the first frame and on a resize, so restart after setting it.
  - The `UWP perf:   D3D12: present:` line now says `sync shared fences` and ends with `GPU waits: copy N, read N`, counting waits enqueued on ANGLE's context and on the queue (a wait already satisfied isn't enqueued). With the fences, `copy-fence wait` stays at 0 ms and `ANGLE read waits` should be 0. On screen, check that frames stay in order: the loading percentage shouldn't flip between values, and the player model shouldn't stutter back and forth.
  - The WARP harness has no ANGLE, so no test covers this. Windows CI and Xbox runs are untested.

## Fixes

- **Direct3D 12: no committed textures** *(untested)*. A texture over the shared heaps' 4 MB class limit, such as a 1024×1024 texture, or one whose placement fails, now gets a heap of its own with a spare 64 KB page after its reported size, instead of a committed resource. In the diagnostic app, a committed texture whose data filled its allocation read `0` at its last texel after any state transition: the Xbox One driver's state word lands inside a committed texture, over its bottom-right texel. The palette lookup table, whose last texel is the entry for white, is placed the same way instead of committed. Committed textures remain only as a last resort when creating a heap fails, logged on first use. The perf summary's `texture heaps:` line now also counts `dedicated` heaps. See [the placed-texture guard](docs/d3d12-texture-placement.md).
- **Direct3D 12: placed-texture guard** *(confirmed on Xbox One X)*. Reserve 4 KB after each placed texture's reported allocation size. The Xbox One driver keeps a 4-byte state word for each placed resource at its data end rounded up to 256 bytes, which `GetResourceAllocationInfo` doesn't count. When a texture's data fills its reported size, the word landed on the next texture's first texel and turned palette-rendered whites black. The texture arena uses alignment-rounded quarter-octave allocation classes (P, 1.25P, 1.5P, 1.75P, 2P), so the guard rarely costs extra memory; static uploads keep their power-of-two classes. See [the placed-texture guard](docs/d3d12-texture-placement.md).

- **Legacy GL: rapid-frame presentation**. Before reusing a presentation slot, wait for ANGLE's GPU to finish reading it, preventing out-of-order frames such as the loading percentage flipping between 0% and 100%. Use per-slot event queries on ANGLE's D3D11 device when EGL device queries are available; otherwise call `glFinish` after drawing frames presented less than 8 ms apart. Read waits give up after 100 ms and count timeouts. Normal shared presentation remains one frame late, and wipe frames still present immediately. The readback path is covered too; its texture upload and draw already share ANGLE's ordering. Confirmed on Xbox One X with ANGLE device queries: frames stay in order, the loading percentage counts up normally, and the player model no longer jumps back and forth. The percentage and model symptoms were the same presentation-slot reuse issue.
- **Track title timing**. On UWP, the animation before a race starts with a fresh clock after loading, so it plays in full. It retains upstream's one animation step per frame and HUD timer clamp. Online VibeRant D3D11 clients instead run the initialized title animation in the normal HUD while simulation catches up, avoiding an extra second of paused simulation after loading. Hosts, Software, offline play and demo playback retain the pre-level animation. This changes presentation timing, not game logic results.
- **Legacy GL: crash drawing sprite-textured models** *(untested)*. A model that uses its sprite's graphics as its texture (such as the item box) read the sprite's hardware data before it existed, which crashed if the sprite hadn't been prepared since video settings last changed (seen on Xbox with 3D models on and shaders off, on Storm Rig). The sprite is now prepared first, and the check for re-fitting the model's texture coordinates compares the sprite's dimensions, as its comment intends, instead of the model texture's, which such models may not have. Applies to every platform built from the patched source.
- **Legacy GL: missing floors and ceilings**. Some floors and ceilings weren't drawn, showing the sky through the track on courses such as Green Hills Zone and Storm Rig. When a level loads, Legacy GL builds one floor/ceiling polygon per subsector by cutting the map along its BSP partition lines. Upstream sent a polygon the cutting line doesn't really split to the front side without checking, and small rounding errors made that happen to polygons lying almost entirely behind the line, so whole groups of subsectors got no polygon and their planes were never drawn. Unsplit polygons now go to the side they actually lie on, and any subsector still without a polygon gets one from its closed GL-seg loop. Across the 149 stock maps with XGL3 nodes, this cuts the missing floor area from about 3.7 million to 11 thousand square units (some, like Sealed Star Gallery, were missing far more than the two reported). Inherited from upstream Legacy GL; applies to every platform built from the patched source. Some subsectors can still get a polygon larger than the subsector, also inherited. Confirmed on Xbox One X: the reported holes on Green Hills Zone and Storm Rig are gone.
- **Options button slide**. On UWP, the button with the submenu's name at the top of the Options submenus (Video, Sound, Voice, HUD, Gameplay, Server, Data, and the profile card in Profile Setup) slides into place once instead of bouncing up and down, sometimes for a long time, when the menus run below 35 FPS. The menu ticks at most once a frame, so a slow frame skips tics. Upstream only ends the slide on a tick at exactly its 5th tic and starts it over from the beginning on any later tick, so a skipped 5th tic made the button jump back and slide again. The slide now starts once and ends on any tick at or after its last tic. Confirmed on Xbox One X.
- **Legacy GL: online delays at race start**. The first fix added keepalives while precaching and building floor/ceiling polygons, at most once per tic. The next Xbox run advanced beyond the earlier 32-tic stall to level tic 98, but the server kicked the player for breaking its delay limit. Basic keepalives reset the connection timeout without updating the server's acknowledged tic count, which it uses to measure delay. UWP VibeRant clients now also send vanilla's `PT_NODEKEEPALIVE`/`PT_NODEKEEPALIVEMIS` header with the actual simulated and buffered tic numbers, at most once per clock tic, without input or a consistency check. The basic keepalive remains for the savegame handshake; the extra acknowledgement is gated to connected clients already in the game, excluding savegame redownloads and demos. The 32-tic receive limit and the server's delay rules are unchanged. Online clients also let the title animate in the HUD rather than pausing simulation for another second after loading. A delay-limit kick logs the last server-reported delay/limit and the local simulated, received and level tics; the server's reported delay may precede the kick. Packet tests and a simulation using upstream's delay-kick logic pass. The Xbox online retest confirmed eight subsequent level transitions, including Angel Island where the earlier run failed, without a delay-limit kick. All eight logged the HUD title path, and the session ended with normal shutdown.
- **Duplicate controllers** (`patches/sdl-controller-duplicates.patch`). Each controller no longer shows up twice when running as a game instead of an app, which made each press count twice.
- **State-change bookkeeping.** The `P_SetMobjState`/`P_SetPlayerMobjState` change under [Game logic](#game-logic) also fixes upstream's unbalanced call count.

## Removed or disabled

- **Crash handlers that can't work in the app container.** The DbgHelp minidump handler, cpptrace stack traces, and the `exchndl` crash handler are gone. The crash logging under [Diagnostics](#diagnostics) replaces them.
- **Legacy GL's OpenGL driver** (`r_opengl.c`) isn't used. The Direct3D 11 port replaces it, with load-time translation for custom GLSL shaders.
- **Master server debugging.** `masterserver_debug`'s verbose curl output and the Windows log-copy helper are only compiled with `LOGMESSAGES`, which is on by default, so this only matters to builds that turn logging off.
